# Patterns

Recurring lessons from killed and parked ideas. Every kill should either match an existing pattern or create a new one. When you create a new idea, check these patterns for matches before you score it; a pattern hit is a cheap way to kill a bad idea before it eats a week.

> **Track tagging:** Patterns may carry an `**Applies to:** solo | venture | both` line; instance suffixes like `(venture)` mark which track an instance came from. Patterns without an `Applies to:` line default to `solo`. Promote a pattern to `both` when an instance appears in the other track.

---

## Pattern 1: Feature, Not a Company

**Applies to:** both

**Constraint violated:** Win the game then exit (primary), Build for the model curve (secondary)

**Description:** The core of the idea is a single feature that any incumbent can ship in a sprint, with no moat underneath it. There is no proprietary data, no workflow lock-in, and no distribution edge, so the moment the idea shows traction the incumbent absorbs it. These ideas can feel good to build because the feature is real and useful, but a feature is not a company: there is no founder-independent path to an exit and no defensible position to build durable value on.

**Triggered by:** HabitMirror (a weekly reflective-summary feature on top of a habit tracker; Defensibility scored 2, no distribution edge, no acquirer path, so it was killed at creation).

**Watch for:** "It is basically X plus a nice summary / dashboard / reminder." A one-sentence pitch that an incumbent could implement without changing their business. Defensibility scoring at 2 or below with no plausible data or distribution moat. Excitement about the build coupled with no answer to "why can't the incumbent just add this?"
